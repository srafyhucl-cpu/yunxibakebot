## 任务清单

**FP-4A 体验版准备（前置：FP-1 + FP-3 阶段一）**

1. 真机验收：真机验证充值页、积分明细、券中心、结算页组合支付入口 UI 与交互。
2. 体验版：上传体验版，覆盖核心流程走查；支付链路以 mock / 本地能力走查（不冒充真实支付）。
3. 审核准备：整理正式审核材料，提交微信官方审核并处理驳回。

**FP-4B1 审核 / 非用户开放版本（前置：FP-4A 完成）**

4. 审核发布：审核通过后以审核 / 内部版本上线，真实用户入口保持关闭；如需提前可见采用"支付关闭版本"。

**受控测试访问模式（FP-4B1 门禁，B1.9 定稿）**

截至 **2027-05-31（含）** 只允许授权测试账号访问，当前任意成功微信登录的 `openid` 均能拿到 JWT、无后端强制边界。因此：

- 服务端访问模式设为 `controlled_test`（可审计、可过期）：**测试账号白名单**（`openid` / 手机号，含授权有效期与操作审计）在**登录换取 JWT 与受保护请求两处**同时拦截——白名单外登录拒绝、白名单过期拒绝、受保护请求校验白名单仍有效；模式与白名单变更留审计日志。
- 正式开放时切换为 `open` 模式：白名单拦截解除（或降级为告警），以 FP-4B2 Go/No-Go 记录为准；切换本身必须登记证据。
- **微信体验者设置只能作为第二道防线**：服务端 `controlled_test` 白名单是主防线，不依赖小程序端体验者名单。
- 实施范围：FP-4B1 前落地并测试（白名单登录拦截、过期、审计、切换 open 的负向用例），验收证据入证据索引。

**FP-4B2 真实用户开放版本（前置：FP-3 阶段二真实支付验收通过 + X1 资产矩阵 + 项目负责人 Go/No-Go）**

5. 真实开放：Go/No-Go 批准后开放真实用户，充值 / 组合支付端到端回验。
6. 发布后回验：`/health` `/ready`、核心 API、账务一致性。
7. 券门禁（B1.9 起**执行既定裁决**，不再三选一）：按 B1.6 裁决执行——**关闭旧有赞小程序券入口**（与有赞运营协调停用）+ **正式版关闭券抵扣**（`ASSET_COUPON_WRITE=disabled`）；真实券测试前做跨端双花检查（同一券两端状态一致、无重复核销），通过后方可开放券抵扣。
8. LOGBOOK / 证据索引收口，使用独立 trace_id。

## 支付关闭版本（仅限 FP-4B1，不面向真实用户）

若真实支付未就绪而需要在审核 / 内部阶段可见，须满足：

1. **支付入口隐藏**：充值页、组合支付差额入口在正式版中隐藏或置灰，仅保留浏览 / 未支付下单能力。
2. **kill switch**：提供后端配置开关，可随时整体关闭支付相关入口与提示，不依赖发版。
3. **二次开放门禁**：从支付关闭版本升级到真实开放（FP-4B2）必须经过 FP-3 阶段二验收 + 服务端资产矩阵（X1）+ 项目负责人 Go/No-Go 门禁。

## 验收标准

- 真机与体验版走查通过，核心流程无阻断。
- FP-4B1：微信官方审核通过，审核 / 内部版本可访问，真实用户入口保持关闭；支付关闭版本入口正确隐藏。
- FP-4B2：真实用户开放仅经项目负责人 Go/No-Go 明确批准；充值 / 组合支付端到端可用；券抵扣三选一 + 真实券测试前跨端双花检查通过。
- 有赞下线（FP-2）前，FP-4B2 已稳定运行并完成回验。
